实现方案对比

方案 A：Bun 静态服务器 + Tauri WebView（推荐）
Bun 内核起一个静态文件服务器（端口如 9777），serve 项目目录。
点击预览 → 前端在右侧 iframe / 新 WebView 加载 http://localhost:9777/prototypes/login.html。
优点：支持 localhost 场景（dev server 预览）、SPA 路由、API 请求。缺点：需要管理端口。
方案 B：Tauri 原生 file:// 加载
直接在 WebView 里加载 tauri://localhost/... 或 file:// 协议读本地 HTML。
优点：零端口管理。缺点：不支持需要 localhost 的 dev server 预览；CORS 限制多。
方案 C：独立窗口（Tauri WebviewWindow）
点击"在新窗口打开" → new WebviewWindow() 弹出独立原生窗口。
优点：独立窗口可调整大小，全屏预览。缺点：不在主界面里，对话和预览分离。

推荐的混合方案：A + C

日常：对话区分屏预览（方案 A）—— Bun 起 localhost:9777 静态服务器，对话右侧 iframe 加载。
大屏：点"⤢"按钮弹独立窗口（方案 C）—— WebviewWindow 全屏看。
支持的场景：
• 静态 HTML 文件 → 直接 serve
• React/Vue dev server → 加载 localhost:3000（用户自己跑的）
• 图片/PDF → 浏览器原生渲染
• Markdown → Bun 转 HTML 再 serve
